# Тихое утро 1.3 — Умная витрина

[Витрина](https://aurones.github.io/TIHOE-UTRO/) · [Кабинет владельца](https://aurones.github.io/TIHOE-UTRO/?mode=owner#/owner)

Посетитель собирает изделия в локальной корзине и сам отправляет текст мастерской. Витрина не запрашивает имя, телефон и адрес покупателя. Продажа готовых изделий приостановлена. В опубликованной демосборке данные редактора остаются в браузере, запросы в TatNet отключены, страницы закрыты от индексации.

## Настройка рабочего TatNet

1. В Studio откройте **Authentication → Settings**. Отключите **Allow new users to sign up** и **Allow anonymous sign-ins**. Оставьте включённым вход по email. В **Authentication → Users** создайте пользователя владельца, включите **Auto Confirm User** и задайте уникальный пароль. Публичная регистрация запрещается на уровне Auth. Сборка рабочего режима проверяет это через публичный endpoint Auth перед публикацией.
2. В файле [tihoe-utro-1.3.sql](supabase/studio/tihoe-utro-1.3.sql) замените единственный `replace-owner@example.invalid` на email владельца. Выполните весь файл одним запуском в **SQL Editor**. Не применяйте старые миграции к новой базе 1.3. SQL создаёт редактор, связывает роль с подтверждённым аккаунтом и настраивает приватный бакет. Если в этом проекте уже были старые таблицы заказов, SQL закрывает их прежние публичные интерфейсы и оставляет данные администратору.
3. После проверки Auth, роли владельца и Storage измените только `mode: 'live'` в [public/config.js](public/config.js) и запустите GitHub Pages. URL и публичный ключ TatNet уже указаны. Индексация управляется отдельно и остаётся выключенной.
4. Войдите по ссылке кабинета. Заполните категории, индивидуальные товары, ткани, главную и контакты. Для Telegram, ВКонтакте и телефона укажите реальные реквизиты мастерской. Сохраните разделы в черновик, проверьте **«Предварительный просмотр»**, затем нажмите **«Сохранить и опубликовать»**. Откройте витрину в другом браузере. Изменения контента появляются после загрузки страницы без запуска GitHub Actions.

Владельца добавляет SQL по ID из Auth. Роль не берётся из редактируемых пользователем метаданных. Секретный ключ для витрины не используется. Статус включения регистрации можно проверить публичным запросом к `/auth/v1/settings`: `disable_signup` должно быть `true`, а `external.anonymous_users` — `false`.

## Публикация и хранение

Редактор сохраняет черновик отдельно. Публикация атомарно обновляет публичный снимок, цены для расчётов и список фотографий, к которым можно получить доступ. Одновременная правка не перезаписывает более новый черновик. При конфликте обновите кабинет и заново внесите несохранённые правки. При сетевой ошибке форма остаётся открытой.

Фотографии сжимаются в JPEG до 1280 px по длинной стороне и хранятся в Storage. Черновые фотографии доступны владельцу. Публичные фотографии выдаются по подписанным ссылкам на 10 минут. Уже выданная ссылка действует до истечения этого срока. Для квоты 100 МБ в PostgreSQL ограничен размер снимка содержимого. Фотографии хранятся отдельно в Storage и учитываются по его тарифу.

Корзина остаётся доступна без сети для копирования. ВКонтакте открывается после копирования текста. Для Telegram короткая подборка открывается как черновик сообщения. Отправку выполняет покупатель в самом мессенджере.

## Индексация и PWA

После официального запуска заполните коды подтверждения в [public/seo.js](public/seo.js) и установите `indexing: true`. Сборка проверит рабочий Auth и наличие опубликованного ассортимента для пошива. Статические canonical, Open Graph и sitemap формируются при сборке. Новые категории становятся доступны в витрине сразу, а их статические SEO-страницы и sitemap обновляются при следующей публикации GitHub Pages. На хостинге проекта robots.txt находится в подкаталоге, поэтому запрет демо дополнительно выставлен метатегом в каждой странице.

Установить витрину можно через меню браузера. Для отдельного ярлыка кабинета откройте его прямую ссылку в Chrome на Android и выберите **«Установить приложение»** или **«Добавить на главный экран»**. Проверка доступа применяется и при запуске с ярлыка.

## Проверки

```sh
npm test
npm run build
npm run dev
```

GitHub Actions отдельно запускает Playwright на демосборке и тестирует SQL, Auth, Storage, публикацию и изоляцию черновика на одноразовой Supabase. Исторические SQL-миграции в `supabase/migrations` сохранены для справки.
