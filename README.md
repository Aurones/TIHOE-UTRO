# Тихое утро 1.0

Семейная мастерская индивидуального пошива постельного белья. «Сшито с любовью. Создано для уюта».

## Запуск

Нужны Node.js 22+ и Python 3. Внешних npm-зависимостей нет.

```sh
npm run dev  # http://127.0.0.1:3000/
npm test
npm run build
```

Сборка для статического хостинга появляется в `dist/`. Маршруты с `#`, картинки и PWA используют относительные пути. Workflow в `.github/workflows/pages.yml` проверяет калькулятор, собирает и публикует `dist/`. В GitHub выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**, затем **Actions → GitHub Pages → Run workflow**. Адрес проекта https://aurones.github.io/TIHOE-UTRO/.

## Демонстрация

При пустых `url` и `key` в `public/config.js` на всех страницах видна отметка «Демонстрационный режим». Ткани и фотографии демонстрационные. Заказы, ткань и настройки сохраняются только в текущем браузере. Внизу сайта откройте «Кабинет владельца», чтобы управлять тестовыми данными. Используйте вымышленные имя и контакт. Чат в этом режиме отключён. Для сброса удалите данные сайта в настройках браузера.

Постановочные изображения созданы для этого проекта средствами генерации. В рабочем каталоге публикуйте фотографии реальных тканей.

## Подключение базы и владельца

1. Проверьте применимость требований к локализации персональных данных. Для заказов российских клиентов выберите инфраструктуру в России, на которой PostgreSQL, Auth, Storage, резервные копии и журналы с персональными данными действительно находятся в России. В качестве варианта рассмотрите самостоятельное развёртывание Supabase на российском сервере или российский сервис с совместимыми API после проверки договора и расположения компонентов. Бесплатный иностранный проект Supabase подходит для проверки на синтетических данных.
2. На тестовом проекте выполните `supabase/migrations/202611260001_init.sql` в SQL Editor. В Authentication включите Anonymous Sign-Ins и настройте ограничения регистрации. Если включаете CAPTCHA на регистрации, понадобится подключить её виджет и передачу токена в `api.js` перед рабочим запуском.
3. В Supabase Authentication создайте владельца с отдельной почтой и сильным паролем, скопируйте UUID. Выполните в SQL Editor под административной учётной записью:
   ```sql
   insert into workshop_private.owners(id) values ('UUID_ВЛАДЕЛЬЦА');
   ```
4. В `public/config.js` укажите HTTPS URL API, клиентский ключ `publishable` или `anon` и ссылку для связи до заказа, например `tel:+7…`. Ключ `service_role`, пароль владельца и любые секреты оставьте вне репозитория. Откройте кабинет, загрузите фотографии тканей, заполните остатки и проверьте настройки расчёта.
5. Обновите политику на странице «Конфиденциальность» в `public/app.js`. Укажите фактического оператора, контакты, основания и сроки обработки, порядок отзыва согласия и удаления. Проверьте необходимость уведомления Роскомнадзора и условия передачи данных. Локализация регулируется частью 5 статьи 18 Федерального закона № 152-ФЗ. Проверьте действующую редакцию перед включением приёма реальных заказов.

### Как устроен доступ

Владелец входит по Supabase Auth. Его UUID разрешён сервером через закрытую таблицу. Покупатель при отправке получает анонимную сессию Auth без обязательной регистрации. Заказы доступны только этой сессии, в том числе после перезагрузки того же браузера. При очистке данных сайта или на другом устройстве доступ требуется согласовать с мастерской. Учётные данные владельца и покупателя хранятся раздельно. Черновик конструктора сохраняется локально, имя и контакт покупателя до отправки сохраняются в памяти открытой страницы.

Таблицы закрыты политиками RLS. Открытый каталог и оценка возвращают ограниченный набор полей. В заказах покупателя отсутствуют себестоимость и заметки владельца. RPC контролируют доступ к сообщениям и ограничивают частоту записи. Фотографии чата лежат в приватном бакете. Для просмотра выдаются подписанные ссылки на пять минут. Перед удалением заказа кабинет удаляет его фотографии из Storage. Для инфраструктуры, отличной от Supabase Cloud, проверьте заголовок доверенного IP прокси или адаптируйте ограничение частоты запросов. Синтетическими аккаунтами проверьте, что чужие заказы, переписки и подписанные ссылки нельзя получить.

### Расчёт и статистика

Одно изделие разбивается на детали. Размер заготовки увеличивается на припуски и усадку. Для простыни на резинке учитываются высота матраса и запас для подгиба, для наволочки с клапаном — запас на клапан. При разрешённом повороте алгоритм проверяет обе ориентации детали, затем укладывает детали рядами по физической ширине рулона. Цена включает пошив, фурнитуру, упаковку, расходы, наценку и скидку. Расчёт оценочный. Раскрой со стыковочными швами, раппорт рисунка и ручные исключения рассчитывает мастер.

Кабинет позволяет скорректировать метраж и себестоимость, указать согласованную цену, полученную сумму и срок. Заказы группируются в карточки по контакту. Аналитика фильтрует по дате заказа, исключает отменённые и показывает согласованные суммы отдельно от полученных денег. Учёт включает сумму оплат на заказ, без отдельного календаря денежных операций. Остатки ткани вводятся вручную.

### Установка и обновление

В Chrome на Android откройте меню ⋮ и выберите «Установить приложение» или «Добавить на главный экран». В Safari на iPhone выберите «Поделиться → На экран Домой → Добавить». Рабочий режим отправляет заказы и сообщения только при доступном интернете.

Service worker обновляется при смене версии сборки и использует сеть в первую очередь. Каталог из базы, запросы авторизации, фотографии переписки и заказы не входят в кэш service worker. При изменении исходников отправьте коммит в `main` и проверьте результат workflow. При использовании собственного хостинга обновите файлы из `dist/` одной публикацией.
